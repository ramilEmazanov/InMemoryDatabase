# InMemoryDatabase — встраиваемая key-value база данных на C++

Локальная база данных, которая хранит строки, списки, множества и географические координаты в памяти процесса. Взаимодействие доступно через библиотечные компоненты и консольное приложение с текстовыми командами — подмножеством команд Valkey.

Основной акцент — проектирование хранилища с несколькими типами значений, разбор команд, управление временем жизни ключей и ограничением памяти. Данные существуют в пределах запущенного процесса.

**Стек:** C++23 · STL · variant/visit · expected · concepts · chrono · CMake · GoogleTest

## Возможности

- **Четыре типа значений:** строки, списки, множества уникальных строк и геопространственные данные.
- **Текстовый интерфейс:** чтение команд из `stdin`, вывод результатов в `stdout`, завершение по `EXIT` или концу ввода.
- **Разбор команд:** нечувствительные к регистру названия команд, строки в кавычках, escape-последовательности и проверка аргументов.
- **TTL:** установка срока жизни ключа, получение оставшегося времени и удаление просроченных записей при обращениях к хранилищу.
- **Контроль памяти:** настройка `maxmemory` при запуске и во время работы, оценка размера значений и проверка роста данных относительно лимита.
- **Геозапросы:** расчёт расстояния, поиск в радиусе, сортировка результатов и сохранение найденных точек в другой ключ.
- **Обработка ошибок:** типизированные ошибки разбора и хранения; после лексической ошибки или неверной команды программа продолжает читать ввод.

## Поддерживаемые команды

| Группа | Команды |
| --- | --- |
| Строки | `SET`, `GET`, `STRLEN`, `APPEND` |
| Списки | `LPUSH`, `RPUSH`, `LPOP`, `RPOP`, `LLEN`, `LRANGE`, `LINDEX`, `LSET`, `LINSERT` |
| Множества | `SADD`, `SREM`, `SISMEMBER`, `SMEMBERS`, `SCARD`, `SUNION`, `SINTER`, `SDIFF`, `SMOVE` |
| Геоданные | `GEOADD`, `GEOPOS`, `GEODIST`, `GEOSEARCH`, `GEOSEARCHSTORE` |
| Время жизни | `EXPIRE`, `TTL` |
| Управление ключами | `TYPE`, `DEL`, `EXISTS`, `KEYS`, `FLUSHDB`, `DBSIZE` |
| Память | `CONFIG SET maxmemory`, `CONFIG GET maxmemory`, `MEMORY USAGE` |

Ключи чувствительны к регистру. Для списков предусмотрены отрицательные индексы, извлечение нескольких элементов и вставка относительно опорного значения. Геоданные возвращают тип `zset` в команде `TYPE`, сохраняя принятую в задании терминологию.

## Технологии и подходы

| Технология / подход | Применение в проекте |
| --- | --- |
| C++23 | Стандарт сборки, `std::expected`, современная работа с типами |
| `std::variant` | Представление значений хранилища, разобранных команд, ответов и ошибок |
| `std::visit` и Overload Pattern | Диспетчеризация команд и обработка разных типов без цепочек ручных проверок |
| Concepts и шаблонные методы | Ограничение допустимых типов и общие операции изменения значений |
| `std::expected` | Передача результата либо типизированной ошибки между этапами обработки |
| `std::unordered_map` | Основной индекс ключей и индекс TTL по имени ключа |
| `std::deque`, `std::unordered_set`, `std::map` | Списки, множества и координаты именованных точек |
| `std::chrono::steady_clock` | Измерение TTL монотонными часами |
| `std::multimap` | Упорядоченный индекс сроков истечения ключей |
| `std::regex` | Поиск ключей по шаблону с преобразованием `*` и `?` |
| GoogleTest и Google Mock | Проверки через библиотечный исполнитель и строковые потоки |
| CMake, FetchContent и CTest | Модульная сборка, загрузка GoogleTest 1.16.0 и регистрация тестов |

## Архитектура

Обработка разделена на независимые этапы: ввод, лексический анализ, разбор команды, исполнение, работа с хранилищем и форматирование ответа.

```text
stdin / входной поток
        ↓
Runner — цикл обработки
        ↓
Tokenizer — токены либо LexicalError
        ↓
CommandParser — ParsedCommand либо ParsingError
        ↓
CommandExecutor — std::visit и специализированные исполнители
        ↓
Storage ← MemoryController / TimeController
        ↓
Reply → ReplyFormatter → stdout / выходной поток
```

### Лексер и парсеры

Лексер реализован как конечный автомат. Состояния чтения обычного слова, строки в кавычках и escape-последовательности представлены через `std::variant`. Ошибки содержат сведения о проблемном символе или позиции.

`CommandParser` нормализует название команды и выбирает функцию разбора из таблицы. Парсеры разделены на группы: строки, списки, множества, геоданные и общие команды. На выходе получается типизированная структура внутри `ParsedCommand`, а ошибки передаются через `std::expected`.

### Диспетчеризация и разделение ответственности

`CommandExecutor` использует `std::visit` и набор специализированных исполнителей: `StringExecutor`, `ListExecutor`, `SetExecutor`, `GeoExecutor` и `GeneralExecutor`.

Каждый исполнитель отвечает за свою группу операций. Хранилище отдельно управляет данными, `TimeController` — сроками жизни, `MemoryController` — учётом памяти. `ReplyFormatter` преобразует типизированный ответ в текст. Добавление команды требует определить её структуру, парсер и обработчик в соответствующей группе.

### Хранение значений

В основном индексе имя ключа связано со значением типа:

```cpp
using Value = std::variant<StringValue, ListValue, SetValue, GeoValue>;
```

Хранилище предоставляет общие методы типизированного доступа, добавления, удаления и изменения значений. Это позволяет переиспользовать проверки типов и учёт изменений памяти в командах разных групп.

### TTL

Сроки жизни индексируются в двух направлениях: по ключу и по времени истечения. Перед рядом операций хранилище запрашивает просроченные ключи у `TimeController` и удаляет их с обновлением счётчика памяти.

Фоновый поток очистки не используется: удаление выполняется при обработке запросов. `TTL` возвращает `-1` для ключа без срока жизни и `-2` для отсутствующего ключа. Команда `SET` сбрасывает существующий TTL.

### Контроль памяти

`MemoryController` хранит текущий оценочный объём данных и лимит. При добавлении или изменении значения вычисляется прирост размера и проверяется возможность выполнить операцию. Нулевой лимит означает отсутствие ограничения.

Оценка основана на `sizeof` типов значений и длине строковых данных и элементов коллекций. Она служит внутренней метрикой хранилища; размер верхнеуровневых имён ключей, индексов TTL и все накладные расходы аллокатора отдельно не учитываются.

### Геопространственные операции

Для именованных точек хранятся широта и долгота. Расстояния вычисляются по формуле Хаверсина с радиусом Земли 6372,8 км. Поддерживаются метры, километры, мили и футы.

Поиск по радиусу перебирает точки, вычисляет расстояния и при необходимости сортирует кандидатов по возрастанию или убыванию, ограничивает количество результатов через `COUNT`. `GEOSEARCHSTORE` сохраняет найденные точки в отдельный ключ.

## Сборка и запуск

Понадобятся CMake версии 3.23 или новее и компилятор со стандартной библиотекой, поддерживающей C++23, включая `std::expected` и `std::format`. GoogleTest загружается через FetchContent при первоначальной конфигурации.

Команды выполняются из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --target labwork10
./build/labwork10 --maxmemory 64mb
```

Имя исполняемого файла в текущем CMake — `labwork10`. Если `--maxmemory` не указан, лимит не установлен. Аргумент поддерживает байты и суффиксы `b`, `kb`, `mb`, `gb`.

Лимит можно изменить после запуска:

```text
CONFIG SET maxmemory 1048576
CONFIG GET maxmemory
```

## Пример работы

Введите команды по одной строке:

```text
SET greeting "Hello C++"
GET greeting
RPUSH tasks parse execute test
LRANGE tasks 0 -1
SADD languages cpp python cpp
SCARD languages
EXPIRE greeting 60
EXIT
```

Ожидаемый вывод:

```text
OK
"Hello C++"
(integer) 3
1) "parse"
2) "execute"
3) "test"
(integer) 2
(integer) 2
(integer) 1
```

Ввод можно перенаправить из файла:

```bash
./build/labwork10 --maxmemory 64mb < commands.txt
```

Пример поиска точек рядом с заданными координатами:

```text
GEOADD places 30.3158 59.9391 spb 37.6173 55.7558 moscow
GEODIST places spb moscow km
GEOSEARCH places FROMLONLAT 30.3158 59.9391 BYRADIUS 100 km ASC COUNT 10
```

## Тестирование

В исходниках определены **122 теста** в семи группах: строки, списки, множества, общие команды, геоданные, память и TTL.

Проверки охватывают создание и изменение значений, ошибочные типы, отсутствующие ключи, отрицательные индексы, операции над множествами, поиск по радиусу, изменение лимита памяти и истечение TTL. Интерактивный интерфейс проверяется через `Runner` со строковыми потоками. Часть тестов времени жизни использует реальные задержки.

```bash
cmake --build build --target labwork10_tests
ctest --test-dir build --output-on-failure
```

## Что демонстрирует проект

- Проектирование встраиваемого хранилища с несколькими типами данных.
- Разделение обработки команд на лексер, парсеры, исполнители и слой хранения.
- Использование `std::variant`, `std::visit` и Overload Pattern для типизированной диспетчеризации.
- Передачу ошибок через `std::expected` и ограничения типов через concepts.
- Реализацию TTL с двумя индексами и контролем времени через монотонные часы.
- Учёт памяти и проверку ограничений перед изменением данных.
- Реализацию геопространственных запросов и тестирование команд через потоковый интерфейс.
